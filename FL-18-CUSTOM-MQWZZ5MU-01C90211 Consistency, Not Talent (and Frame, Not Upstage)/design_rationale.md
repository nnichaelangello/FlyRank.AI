# Design Rationale & Visual Identity

## 1. Frame, Not Upstage
The core identity of my portfolio revolves around a sleek, dark-mode aesthetic utilizing glassmorphism (`glass-card` classes). This wasn't just a stylistic choice—it was a strategic one. A portfolio's job is to frame the work, never upstage it. By keeping the background dark (using subtle CSS animations like the spotlight and noise overlay) and the typography clean and monochromatic, the vibrant colors of my actual case study images naturally become the focal points. The UI fades into the background so the engineering work can shine.

## 2. Image Judgment: Screenshots over Generation
While generative AI can produce thousands of flawless images in seconds, I deliberately rejected using AI-generated art for my core case studies (AKSARA and PRISMA).
- **Why?** Generating a "hacker typing on a keyboard" image to represent a Federated Learning project looks amateurish and tells the viewer nothing. 
- **The Choice:** Instead, I used real, raw screenshots of the PRISMA dashboard and the AKSARA web interface. A real screenshot of actual working software—even if the UI isn't perfect—proves that I can actually build and ship software, which is infinitely more valuable to an employer than proving I can write a midjourney prompt.

## 3. Strategic AI Image Use
I did use an AI-generated image for the "AI-Based CCTV Workforce Tracking" case study (the blue isometric factory grid).
- **The Selection Process:** I generated several options. I rejected the hyper-realistic ones because they looked too chaotic and distracting. I specifically chose the subtle, blueprint-style texture (`hero_texture_accepted.png`) because it conceptually matched the idea of "workforce tracking" without demanding too much visual attention, adhering to the *Frame, Not Upstage* philosophy.
